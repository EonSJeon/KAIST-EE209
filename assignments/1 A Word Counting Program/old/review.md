# 과제 1 원본 리뷰

## 판단과 요구사항

PDF 제목은 **A Word Counting Program**이다. 원본의 6상태 DFA는 유지할 가치가 있다. 정상 입력에서 확인한 PDF 예제, 주석 경계, 중첩처럼 보이는 주석, 임의 입력을 합친 317개 정상/문법 사례가 독립적인 decomment/count 기준과 일치했다. 따라서 원본이 틀렸을 것이라는 추측만으로 전이 로직을 바꾸지 않았다.

이 과제는 일반적인 `wc -l`과 줄 수가 다르다. 빈 파일은 `0 0 0`, `abc\n`은 `2 1 4`이며, 주석은 공백 하나로 바꾸고 주석 안의 개행도 문자로 센다. 따옴표나 `//`를 별도 주석 문법으로 추가하지 않았다.

## 표시한 문제

`old/wc209.c`에서 읽기 반복문 앞의 `WRONG:`을 확인하면 된다. `getchar()`의 `EOF`는 정상 종료와 읽기 실패 양쪽에서 나온다. 기존 코드는 `ferror(stdin)`을 확인하지 않아 입력 실패도 성공으로 보고한다. 이것은 PDF의 정상 텍스트 예제에서 드러나는 계산 오류가 아니라 방어적 오류 처리의 누락이다.

## 유지한 점과 바꾼 습관

- `/`를 보자마자 단어를 확정하지 않고 다음 문자를 기다리는 구조는 올바르다. `START_COM_OUT`과 `START_COM_IN`을 합치면 단독 `/`와 주석 시작을 잘못 셀 수 있다.
- `IN_COM`과 `END_COM`을 나눈 구조는 `/***/`의 연속 `*`를 정확히 처리한다.
- 반환값 하나를 성공/실패로 단정하지 말고 스트림 상태를 함께 확인하는 습관을 추가하면 좋다.
- 함수 선언의 빈 `()` 대신 `(void)`를 쓰고 외부에 공개하지 않는 helper를 `static`으로 제한했다. 이는 기능 오류 수정보다 인터페이스 명확화다.
- 이 과제 PDF는 전역 변수 사용을 허용한다. 원래 전역 변수 구조를 무조건 잘못이라고 표시하지 않았다.

## corrected 대응

`wc209.c`의 `CORRECTED:`는 위 변경만 설명한다. 기존 DFA·변수명·카운팅 순서를 유지했다. `dfa`에는 그 구현과 대응하는 텍스트 전이표를 추가했다. 실제 디렉터리 descriptor를 stdin으로 전달하는 읽기 실패 사례도 추가했다. `run.sh --build`는 `.i`, `.s`, `.o`, 실행 파일을 각각 만든다.

```sh
./run.sh --test
printf 'abc/*def*/ghi\n' | ./run.sh
```

위 명령은 `corrected` 디렉터리에서 실행한다. 검증 기준은 제공 PDF와 새로 작성한 테스트이며, 보관본에 없는 수업 공식 `samplewc209`와의 비교 결과를 뜻하지 않는다.
