# 과제 4 원본 리뷰

## 판단과 요구사항

PDF 제목은 **Assembly Language Programming**이다. 실제 프로그램은 IA-32 postfix 계산기 `mydc`다. 원본의 ESP 기반 피연산자 스택, 입력/연산 분기 이름, 정수 계산 구조를 유지했고, C 컴파일러로 계산기를 대신 만들지 않았다.

## 실제 오류와 개념

| 위치 | 왜 틀리는가 | 필요한 개념 / 수정 |
|---|---|---|
| `scanf("%s")` | 20바이트 buffer를 넘어 쓸 수 있다. | 경계 검사, 긴 토큰 전체 소비 |
| `isdigit` 뒤 ECX 사용 | ECX는 caller-saved이며 호출 뒤 보존되지 않는다. 특정 libc에서 우연히 유지돼도 규약상 의존할 수 없다. | 호출 규약; 수정본은 libc 없이 전체 숫자 검증 |
| `atoi` | `12abc`도 12로 받지만 PDF는 혼합 입력을 무시하도록 요구한다. | 접두사 변환과 전체 문법 검사의 차이 |
| 지수 루프 | 지수 0인데 곱셈부터 시작해 카운터가 음수로 계속 감소한다. | 반복 불변식, 0회 반복, 별도 `power` 함수 |
| 음수 나눗셈 | `INT_MIN`은 `neg`로 양수가 되지 않는다. | `cltd`로 EDX:EAX 부호 확장 후 `idiv` |
| 나머지 | 음수 피연산자를 무시하면서 pop한 값은 잃는다. | signed 나머지와 오류 시 상태 보존 |
| `r` | 스택 전체를 역순으로 바꾼다. PDF의 요구는 상위 두 값 교환이다. | 연산의 정확한 범위 |
| 빈 `f`/`c` | 아무것도 하지 않아야 하지만 stack empty를 출력한다. | 명령마다 다른 오류 조건 |
| main의 레지스터 | EBX/ESI를 바꾸고 호출자에게 복구하지 않는다. | callee-saved 규약 |

수정본은 `printf`/`getchar` 호출 전 스택도 16바이트에 맞춘다. 피연산자 스택 깊이가 달라져도 C 호출 스택 정렬은 지켜야 한다. `twoOpds`는 먼저 두 값의 존재를 확인하고, 연산이 성공할 때만 원래 두 값을 결과로 바꾼다.

## 대표 반례

`1 2 3 r f`는 위부터 `2, 3, 1`이어야 한다. `2 0 ^ p`는 `1`이어야 한다. `_7 3 % p`는 `-1`이어야 한다. `12abc p`는 숫자를 추가하지 않았으므로 `dc: stack empty`다. 실제 입력은 각 토큰을 줄바꿈으로 구분하면 된다.

## 이 코드에서 바꾸면 좋은 습관

레지스터를 변수처럼 사용할 때마다 함수 호출이 그 값을 지울 수 있는지 적는다. 루프는 0/1/일반값을 먼저 확인한다. 두 값 예제만으로는 `r`의 전체 역순 오류가 보이지 않으므로 세 값 이상도 쓴다. 오류가 나도 피연산자를 불필요하게 파괴하지 않는다.

## corrected 검증과 실행 환경

지수 0·큰 지수·INT_MIN·음수 나눗셈/나머지·스택 부족·혼합 문자열·긴 토큰·200개 스택 출력·임의 산술을 검사했다. PDF가 허용하는 범위 밖 동작인 0 나눗셈도 수정본은 메시지를 출력하고 스택을 유지한다. 범위 밖 정수 토큰은 무시한다.

```sh
./run.sh --test
printf '2\n0\n^\np\nq\n' | ./run.sh
```

명령은 `corrected`에서 실행한다. Apple Silicon에서는 Clang이 만든 **실제 i386 ELF object**를 Unicorn으로 실행한다. 이는 이 과제와 precept에 필요한 libc 연결만 제공하는 교육용 실행기이며 Linux OS 전체나 공식 32비트 채점 환경을 재현한 것은 아니다. 샌드박스가 JIT 실행을 막는 경우는 일반 터미널에서 실행해야 한다.
