# 과제 2 원본 리뷰

## 판단과 요구사항

PDF 제목은 **String Manipulation**이다. `Str`의 포인터 순회 구현과 `sgrep`의 find/replace/diff 분리는 유지했다. `StrSearch`의 되돌아가며 찾는 방식은 단순하지만, 검사한 빈 문자열·반복 접두사 사례에서 맞았다. 근거 없이 그 부분을 버그로 표시하지 않았다.

## 실제 오류와 영향

| 위치 | 왜 문제가 되는가 | 필요한 개념 | 최소 수정 |
|---|---|---|---|
| `StrCompare` | signed `char` 환경에서 `0x80`과 `0x01`의 비교 부호가 표준 `strcmp`와 달라진다. | 바이트의 signedness, 표준 함수 계약 | 비교 차이를 `unsigned char`로 계산 |
| `DoDiff` 출력 | 원래 `파일@line2:내용`은 PDF 예제의 `파일@2:내용`과 다르다. | 출력 형식도 인터페이스라는 점 | `@%d:`로 변경 |
| `DoDiff` 조기 EOF | 줄 번호를 올리기 전에 오류를 출력해 첫 줄의 EOF를 0이라고 보고한다. | 현재 처리 위치와 완료된 개수의 구분 | 현재 검사 줄을 먼저 증가 |
| 두 번째 `fopen` 실패 | 첫 번째 파일을 이미 열고도 닫지 않는다. | 실패 경로의 소유권 | 첫 FILE을 닫은 뒤 반환 |
| diff 반복문 반환 경로 | 성공/길이 오류/EOF 오류에서 두 스트림을 닫지 않는다. | 한 번 획득한 자원의 한 번 해제 | 결과를 정하고 공통 cleanup |
| `fgets` 실패 | 정상 EOF와 I/O 오류를 구분하지 않는다. | 스트림 오류 상태 | `ferror` 검사 |

`DoReplace`가 반환된 `size_t` 길이를 `int`에 넣는 부분도 표시했다. 허용된 1023바이트 인자에서는 실제 범위 초과가 생기지 않으므로, 이를 그 범위 안에서 반드시 터지는 버그라고 해석하면 안 된다. 타입 계약을 유지하도록 보완한 부분이다.

## 바꾸면 좋은 습관

ASCII 몇 글자만으로 문자열 라이브러리를 검증하지 말고 모든 바이트 순서를 확인한다. 포인터는 주소이면서 소유권의 시작점이므로 성공 경로뿐 아니라 조기 반환도 따라가 본다. 출력 문자열에 관습적으로 단어를 덧붙이지 말고 요구 형식과 직접 비교한다.

## corrected 대응과 검증

원래의 다섯 문자열 함수, 포인터 순회, 작은 입력 버퍼, 스트리밍 치환을 유지했다. `str.c`와 `sgrep.c`에서 표준 문자열 함수를 호출하지 않는다. 치환 결과가 입력보다 훨씬 길어져도 큰 결과 배열이나 동적 할당을 만들지 않는다. `str.h`는 `size_t`를 표준 `<stddef.h>`에서 가져온다.

`test_str.c`는 65,536개 단일 바이트 비교와 빈/반복 문자열·반환 포인터를 libc와 비교한다. 프로그램 검사는 1023/1024바이트 경계, 빈 검색/치환, 겹치는 검색 문자열, 큰 치환 결과, diff 형식·조기 EOF·열기 실패를 포함한다.

```sh
./run.sh --test
printf 'ababa\n' | ./run.sh -r aba X
./run.sh -d first.txt second.txt
```

명령은 `corrected`에서 실행한다. 공식 수업 테스트 클라이언트는 이 보관본에 없어 자체 회귀 클라이언트를 추가했다.
